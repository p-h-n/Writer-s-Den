I have gotten the Add Project and Load Project buttons on the menu working.

The Add Project logic was easier to create than the Load Project logic. I wrote a single public void method called addNewProject(), which prompts the user to enter a name for the new project. The name entered becomes the name of the project directory, and two subdirectories, Outline and Transcript, are created inside it.

I used a JOptionPane to take in the project name. I then created two path variables for the Outline and Transcript directories, using a global string variable containing the project directory as a baseline. I wrapped the logic in a try-catch block to check whether the Outline and Transcript directories already existed and whether they were created successfully. Two exceptions were defined: one for when the directory already exists, and one for when the directory could not be created.

However, the error messages I set up to be displayed are not appearing, even when a new project is given the same name as an existing one. What I have observed is that no new project is created, and no duplicates appear. The problem is that the user is not informed of this and can only discover it by checking the existing projects, none of which are removed or changed. I will investigate this further in the future, but for now the project creation feature works.

The Load Project feature was considerably more challenging. The desired result was a new frame or menu displaying the existing projects. I did not know how to implement this, and I could not find any online information on how to create it.

I understood that something akin to a for loop was needed to scan through the names inside the Projects folder, take the name strings, assign each a button and display them. I simply did not know which methods and imports I needed.

To find out, I built a small skeleton of what I believed was required. I created the skeleton of a new frame, added an action listener for Load Project (although it contained no logic yet), and created the skeleton of a loadProject() method. I then asked GitHub Copilot what was needed to create a new frame that displays the existing projects.

The output was a new method in ProjectsManager.java and a new file called ProjectFrame.java.

In ProjectsManager.java, a new public Path method returns the path to the Projects folder. There is also a new listProjects() method, which returns a List and throws an IOException. This method places the Projects directory into a Path, checks that it exists and is a directory, and returns a list of the files inside the Projects folder.

In ProjectFrame.java, a new JFrame class was created. It has a header and uses a DefaultListModel (DLM), whose contents are placed into a JList. A try-catch block then uses forEach to achieve something similar to a for loop, adding each project to the list one by one. The class also checks whether any projects exist and, if none are found, displays a “No projects found” label.

These files work together with the rest of the code, and after reviewing and studying them, I can say that they will do for now.

I am concerned that as this project progresses, online resources may begin to run out. I may therefore have to rely much more heavily on AI agents to explain which tools, imports and methods are available for the features I want to build, provided my books and other sources do not help.
